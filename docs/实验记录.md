# 实验记录

每次只改**一个**东西，其余全部固定，然后看分数怎么动。

这张表的作用不是记录"我做了什么"，而是回答面试里那句追问：**"你怎么知道是那个改动起作用了？"**
如果两个地方一起改，分数涨了也说不清是谁的功劳。

---

## 前置：先校准尺子（2026-11-18）

在记录任何实验之前，先怀疑判定逻辑本身。初版 `judge()` 只有三个检查，跑出 **15/15（100%）**。
自查后发现四处漏检：

| 漏检点 | 后果 |
| --- | --- |
| `should_refuse` 分支先 `return`，`must_not_contain` 永远不执行 | 一边说"我无权查看"一边泄露他人退款金额 → 判通过 |
| 库内题答"资料中未提供" | 等于放弃作答，却判通过 |
| 不校验答案里的 `[n]` 指向哪份文档 | 引错文档、或完全不标引用，都判通过 |
| 版本冲突题不校验错误值 | 问 15 天，答已废止的 7 天，也判通过 |

修正后同一批题、同一版 prompt → **14/15（93%）**。

> 15 → 14 不是退步，是尺子校准。修正前的 100% 是无效数据，不能写进任何地方。
> 这一条本身比后面任何实验都值钱：**评测集的第一道防线是判定逻辑，不是模型。**

## 实验 1：system prompt 规则 2 拆分

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-11-18 |
| 变量 | `rag.py` 的 SYSTEM 规则 2 |
| 固定 | 检索层（BM25 / 切分 400-80 / TOP_K=3）、判定逻辑、评测集 15 题、模型参数、温度（未设，用服务商默认） |
| 成本 | ￥0.0318 |

**改法**

改前：`资料里没有答案 → 回答「这个问题我需要转人工客服确认」，绝对不要猜。`

改后拆成两支：

- a) 资料写了相关规则、只是没有具体结论（如只写"赔付金额一律转人工"）→ **引依据再转人工**，如「按工单升级规则，涉及赔付金额一律转人工 [1]」
- b) 资料完全没提到 → 只转人工，**不标引用**

**结果**

| | 通过率 | 失败项 |
| --- | --- | --- |
| 改前 | 14/15（93%） | 第 10 题：答「转人工」但没标引用编号 |
| 改后 | **15/15（100%）** | 无 |
| 平均耗时 | 1.63s | 单题均价 ￥0.00212 |

**结论**

模型本来就知道该转人工（关键词命中），缺的是"转人工也要给依据"这条指令。
所以这是 **prompt 表述的缺口，不是检索错了，也不是模型答不出**。
对照证据：检索层第 10 题一直以 16.38 分排第一，资料从头到尾都在正确位置。

**为什么拆成 a/b 而不是直接写"所有回答都必须标 [n]"**

库外题的资料里确实什么都没有，硬要求引用等于逼模型编一个来源。
a/b 拆法的实质是把「**有依据的转人工**」和「**真没资料的转人工**」分开，让引用只在有依据时才被要求。

**局限（必须一起写，否则这个 100% 又变成假数据）**

1. 15 题样本太小，单条失败翻转就能让分数跳 7 个百分点，**不能外推**。
2. 评测集是围绕这 10 份文档自己出的题，等于"考自己写过的题"，难度低于真实分布。
3. 第 10 题单条通过，不能推出"所有赔付类问题都会引依据"——要验证得加题，不是加结论。
4. temperature 未显式设置，依赖服务商默认值。这意味着**换模型后这个分数不可直接比较**。
